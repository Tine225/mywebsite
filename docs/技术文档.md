# 个人网站 · 技术文档

## 1. 技术栈

| 分类 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Next.js 16.4.3（App Router） | 全栈框架，同时承担前端渲染与后端接口 |
| 语言 | TypeScript 5 | 类型安全 |
| UI 样式 | Tailwind CSS 4 | 原子化样式 |
| 数据库 | Neon（Postgres 云） | 生产环境持久化内容 |
| 数据库驱动 | @neondatabase/serverless | 无连接池的 HTTP 驱动，适配 serverless |
| 部署 | Netlify | 免费额度，Next.js 运行时 |
| 包管理 | npm | — |

## 2. 总体架构

```
访客 ──▶ Next.js 页面（服务端组件，动态渲染）
             │  读取
             ▼
       存储层 lib/storage.ts
        ├── 生产：Neon Postgres（DATABASE_URL 存在时）
        └── 本地：.data/content.json（无 DATABASE_URL 时）

管理员 ──▶ /admin/login ──▶ 会话 Cookie ──▶ /admin（校验会话）
             │                                    │
             └──── AdminEditor（客户端组件）────────┘
                       │ PUT /api/content（鉴权）
                       ▼
                  存储层 saveContent()
```

要点：

- **前台页面**是服务端组件，直接调用 `getContent()` 读取存储，**动态渲染**（每次请求读最新数据）。
- **后台编辑**是客户端组件，通过 `GET /api/content` 拉取、`PUT /api/content` 保存。
- **数据存储**抽象成 `getContent()` / `saveContent()`，根据是否配置 `DATABASE_URL` 自动在「Neon」和「本地文件」之间切换。

## 4. 数据存储设计

### 4.1 存储抽象

`lib/storage.ts` 暴露两个函数：

```ts
export async function getContent(): Promise<SiteContent>
export async function saveContent(content: SiteContent): Promise<void>
```

内部逻辑：

- **存在 `DATABASE_URL`** → 使用 Neon：
  - 表 `site_content`（`id integer PRIMARY KEY`、`data jsonb`、`updated_at timestamptz`）；
  - 表在首次访问时通过 `CREATE TABLE IF NOT EXISTS` 自动创建；
  - 只使用 `id = 1` 一行保存整个 `SiteContent` 文档；
  - 写入使用 `INSERT ... ON CONFLICT (id) DO UPDATE`（upsert）。
- **不存在 `DATABASE_URL`** → 使用本地文件 `.data/content.json`（已 gitignore）。

### 4.2 内容清洗

`lib/content.ts` 的 `sanitizeContent()` 在写入前对管理员提交的数据做类型收敛与兜底：

- 字段统一转为字符串/数字/布尔，缺失时给默认值；
- `level` 收敛到 0–100；
- `tags` 过滤空项；
- 缺失 `id` 时自动生成 UUID。

## 5. 认证与会话机制

`lib/auth.ts` 实现：

- **密码校验**：`verifyPassword()` 对输入与 `ADMIN_PASSWORD` 分别做 SHA-256 哈希后，用 `crypto.timingSafeEqual` 恒定时间比较，避免时序侧信道。
- **会话令牌**：`createSessionToken()` 生成一个 JSON 负载（含过期时间 `exp`），用 HMAC-SHA256 签名，整体 `base64url` 编码。
- **签名密钥**：优先取 `SESSION_SECRET`，否则回退 `ADMIN_PASSWORD`，再回退本地开发默认值。
- **校验**：`verifySessionToken()` 校验签名是否匹配、是否过期（7 天）。
- **Cookie**：`admin_session`，`httpOnly`、`sameSite=lax`、生产环境 `secure`、`maxAge=7 天`。

## 6. API 接口说明

| 方法 | 路径 | 鉴权 | 请求体 | 成功响应 | 失败响应 |
| --- | --- | --- | --- | --- | --- |
| POST | `/api/auth/login` | 否 | `{ password }` | `{ ok: true }` + 会话 Cookie | 401 `{ error }` |
| POST | `/api/auth/logout` | 否 | — | `{ ok: true }`，清除 Cookie | — |
| GET | `/api/content` | 否 | — | `SiteContent` JSON | — |
| PUT | `/api/content` | 是 | `SiteContent` JSON | `{ ok: true }` | 401 / 400 |

写接口鉴权：从请求 Cookie 读取 `admin_session`，调用 `verifySessionToken()` 校验，失败返回 401。

## 7. 页面渲染说明

- 首页、技能页、项目页、后台入口页均声明 `export const dynamic = "force-dynamic"`，保证每次请求都读取最新内容（内容改动无需重新部署）。
- 登录页是静态客户端组件，不依赖服务端动态数据。
- 后台编辑页 `AdminEditor` 在客户端 `fetch('/api/content')` 拉取数据，编辑后 `PUT` 保存。

## 8. 环境变量

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `ADMIN_PASSWORD` | 是 | 管理员登录密码 |
| `SESSION_SECRET` | 否 | 会话签名密钥（建议配置随机串） |
| `DATABASE_URL` | 生产环境是 | Neon 连接串；不配置则用本地文件存储 |

本地开发用 `.env.local`；生产在 Netlify 项目 `Environment Variables` 中配置。

## 9. 部署（Netlify）

1. 本地 `netlify login` 登录；
2. `netlify deploy --prod` 创建/更新站点并部署，Netlify 自动识别 Next.js 并使用 Next.js 运行时构建；
3. 在 Netlify 项目设置中配置 `ADMIN_PASSWORD`、`SESSION_SECRET`、`DATABASE_URL`；
4. 首次访问时 `site_content` 表自动创建；
5. 可选：绑定自定义域名。

> 说明：项目关闭了 Next.js 16 默认的 `cacheComponents` / `partialPrefetching`（`next.config.ts` 中未启用），以兼容 Netlify 本地 CLI 部署时的 Blobs 上传环节。

## 10. 本地开发

```bash
npm install
# 编辑 .env.local 设置 ADMIN_PASSWORD
npm run dev        # http://localhost:3000
npm run build      # 生产构建
npm run lint       # 代码检查
```

本地未配置 `DATABASE_URL` 时，内容写入 `.data/content.json`；后台地址 `/admin/login`，默认密码见 `.env.local`。
